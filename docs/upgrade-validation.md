## Current local-only image and key workflow

New student, classroom and ordinary teacher PDF uploads are enforced as local-only, including forged method values. Earlier sections below describe historical provider implementations; those modes are **not offered by the current upload screens**. Historical provider code and records are retained. Separately enabled answer-suggestion features remain opt-in and do not confirm keys automatically.

The owner may type, paste, or locally read JPEG/PNG answer-key photos. OCR produces **single-choice suggestions only**, highlights missing, duplicate, unclear, unmatched or unsupported entries, and requires explicit comparison and human confirmation. A correct paper/set and printed-choice mapping must be checked. Installing the normal requirements adds English data to the Python environment for the local PyMuPDF key-photo reader; a valid `TESSDATA_PREFIX` takes precedence (see the README). The app neither downloads OCR data at read time nor sends key photos to a provider. Scanned PDF extraction has separate dependencies and may still require a Tesseract executable and Hindi data. OCR can misread even clear text. The later supplied key photo was tested locally as described below; its relationship to any particular source PDF was not verified.

Review and CBT prefer original question images, with ordered parts for continuation pages and accessible fallbacks when images are incomplete or fail. Same-page source regions are combined from original pixels while preserving their saved provenance; reviewers are warned to check the composite. A reviewer can explicitly select image-only choice labels without inventing option text. Known crop gaps, unavailable files and possible printed answers produce warnings and repair links, but detection is heuristic and not exhaustive. Student bank image repairs use copy-on-write so past tests keep their original version; public bank edits may display updated material in older exams.

Reviewed single-correct, multiple-correct and numerical answers can be graded with the necessary confirmations. Multiple-correct questions support an exact set or a fixed per-correct-choice partial award for a proper subset (capped at full marks), with a configured penalty for a wrong selection. Numerical questions use a checked value and non-negative symmetric tolerance. Other marking schemes, such as asymmetric numerical ranges or more complex JEE Advanced rules, are not implemented; do not claim an exact official score for those schemes. Missing or ambiguous keys remain ungraded, and partial-key institutional results are unranked rather than labelled failed. New typed decisions snapshot the response, checked key, rules, outcome and checked explanation. Older attempts without snapshots keep their recorded scores and decisions, disclose missing key details and are not silently regraded. Legacy multi/numerical option flags are not automatically verified; an old single-option response is preserved until the candidate explicitly re-answers or clears it. For an existing deployment, back up the database and files, then apply `python manage.py migrate`; the project database was not modified by the tests.

**Previous validation checkpoint:** the complete Django run executed 523 tests successfully with 7 skips, using a disposable file-backed database and all 17 Chromium workflows. Six skipped local OCR tests were subsequently rerun with English/Hindi language data and passed; the optional original-PDF regression remained skipped because its fixture was not configured. Django checks, migration drift, dependency checks, JavaScript syntax and `git diff --check` passed. ## What changed (historical checkpoints)

These notes describe behavior at the time of those earlier milestones. In particular, new classroom, series and private tests now allow one attempt per test identity, with resume of an active attempt; historical retakes remain in records. Packs and one-time free allowances have replaced the earlier new-subscription model.

- **Teacher-led classroom tests with join codes (new).** A teacher runs any of their published tests as a `ClassroomSession` with an unpredictable, collision-safe join code (unambiguous alphabet, server-generated with retry). Students enter the code from their dashboard ("Join Test with Code"), which registers a `ClassroomParticipant` (idempotent — a reconnect never double-counts) and routes them to a per-session entry screen; starting creates a session-scoped `ExamAttempt` on the existing server timer, and refresh/reconnect/re-join resumes that same attempt (a DB constraint `one_active_classroom_attempt` plus `select_for_update` prevent duplicate/concurrent attempts). The teacher gets a live owner-only session dashboard (polled every 5s) with **distinct** counts — joined, started, in-progress, submitted, timed-out — a searchable/paginated participant list, Copy-Code/Copy-Link, an optional locally-generated QR (via the optional `segno` package; degrades to copy actions if absent), controls to open/close joining (closing never ends existing attempts), regenerate the code, and an explicit confirm-gated "End test now" (which submits in-progress attempts, preserving answers). Scoring reuses the **confirmed-key-only** server path (a teacher-confirmed key = `answer_status=manually_verified` with one correct option; private practice uses `key_verified`); missing keys are "awaiting key", never wrong. The session leaderboard is private to the teacher by default (opt-in for students), ranks only graded attempts, breaks ties by fewer-incorrect then faster, and uses each student's best attempt when retakes are enabled. Results export to CSV. There is **no application-imposed participant cap**, sessions are isolated per teacher and per session, question images are served only through the existing authorized routes, and joining never touches private-practice/premium limits or institutional categories.
- **Full-screen CBT entry + Strict Exam Mode (new).** The session page shows an explicit "Enter Full Screen & Start Test" gate that requests full screen from a user click (never on load/navigation), with a usable full-window fallback when the API is unavailable (e.g. some mobile browsers) and a "Return to Full Screen" prompt if the student exits on a supported device (logged separately, not counted as a tab switch). Teachers can enable a disclosed **Strict Exam Mode** per test: distinct page-switch (visible→hidden) episodes are counted **on the server**, idempotently per client-generated episode id (`ExamSecurityLog.client_event_id`, unique per attempt), warnings 1–3 of 3 are shown, and the **4th distinct episode ends the attempt for review** (`ExamAttempt.status=TERMINATED`, `is_security_locked`) while **preserving and scoring saved answers**. The count is separate from the pre-existing mixed deterrent counter (`anti_cheat_warnings`), survives refresh/reconnect (it is server-authoritative), and is safe against submit/timeout races (`select_for_update`). Window blur, full-screen exit, copy and zoom are logged but never counted as page switches. The original timer/expiry is always resumed, never reset. Teachers see the event history and counts on the result page, framed as reported signals (not proof of cheating); nothing silently changes other exams or private practice. Limitation: a browser cannot reliably distinguish a tab switch from a phone call or screen lock — this is disclosed to students, and client-reported events are not claimed to be tamper-proof.
- **Image-first practice (new).** Uploads default to an "image-first" mode in which each question is shown in the CBT as a high-resolution crop of the original PDF (statement, printed options, formulas, tables and diagrams), with clear A/B/C/D buttons below. Crops are rendered locally from the already-stored per-question source regions (`image_first.py`, via the existing `page_image` renderer) and saved as `question_crop` figures. Extracted text remains available to screen readers, with visual text and source regions automatically shown if a crop is missing, incomplete or fails to load; OCR can be inaccurate. Answers bind by option **id**, so the 1-4 → A-D mapping and confirmed-key-only scoring are unchanged; options are never shuffled for an image-first question, so the buttons always match the printed image. A best-effort, explicitly non-exhaustive heuristic flags crops that may contain a printed answer/solution (`crop_warning`) so the reviewer can recrop or remove them via the existing figure-management tools. Applies to both private student practice and teacher public exams (`Exam.image_first_mode`, `Question.is_image_first`, `ExtractedQuestion.is_image_first`).
- **Simplified, local-only upload (new).** The teacher and student upload screens do not ask users to select an extraction method. Processing is enforced locally on the server: an omitted method defaults to local and any other value is rejected with a clear error rather than silently run. Cloud/MinerU provider code, configuration and migrations are preserved for future use; no user data is deleted.
- **Optional local vision comparison (new).** The post-submission local AI comparison can now use an operator-configured LOCAL vision model (`LOCAL_PRACTICE_AI_VISION_MODEL`) for image/image-first questions; the crop image is sent only to the local Ollama instance, the student's chosen answer is never in the prompt, and the match is computed locally. With no vision model installed, image questions show an honest "unavailable" state instead of guessing. Results remain estimates, clearly separated from verified scoring.
- Local digital-PDF extraction now retains question page/normalized regions, detects some ruled tables and merged cells, conservatively reconstructs certain superscripts, fractions and simple radicals, and flags uncertain mathematical/table content for review. Automatic figures are original-PDF crops; reviewers can attach, replace, retarget or crop multiple question/option figures. Cloud extraction validates optional structured tables and source-region suggestions, with human review required.
- Structured tables are escaped and rendered as real responsive HTML, with math rendering in cells and options, in staging, bank, CBT and results. The cell editor supports adding/removing rows and an advanced representation for spans. Assertion–Reason and statement labels are visually distinguished when recognized.
- Optional Gemini answer suggestions are consent-gated, model-configurable, validated and kept separate from grading keys. Reviewers can accept, edit or reject them. Missing/low-confidence/vision-dependent answers remain unconfirmed. The staging page offers a bounded queue of up to five **separate** requests; unchanged pending/suggested requests are deduplicated. Student plans provide configurable quotas; provider calls, reported tokens and optional cost estimates are recorded.
- Private practice at this historical checkpoint was owner-scoped with private files, server-side fixed expiry, reattempts and confirmed-key-only scoring. **New private tests now permit one attempt**, with the same active attempt resumed after reconnect; old results remain. Results distinguish correct, incorrect, unattempted and answered-but-ungraded, show attempted totals and excluded keys, and include subject/topic, time and report views. Student bank edits use copy-on-write to protect existing private-test history. Institutional exam settings are not changed by a private test's duration. Razorpay remains test-mode-only with server verification.

## Question-type detection and multi-drive storage follow-up — 2026-11-12

- **Local, free question-type detection.** Previously every extracted item was treated as a single-correct MCQ, so a numerical/integer-value question looked like a *broken* MCQ ("only 0 options detected") and a multiple-correct or subjective question was silently mishandled. A new heuristic (`apps/questions/question_types.py`) now inspects the already-extracted statement and options and labels each staging item as single-correct MCQ, multiple-correct MCQ, numerical/integer-value, or subjective/essay. It runs entirely offline — no network, API key, model weights or paid service — and never invents answers, options or content; it only sets an advisory `ExtractedQuestion.detected_type` and a review flag. Detection is deliberately conservative: multiple-correct requires an explicit printed marker (e.g. "one or more", "more than one", "select all that apply", "is/are correct", Hindi "एक या अधिक"); numerical requires an answer-shaped cue (e.g. "nearest integer", "numerical value", "round off", "…decimal place", a fill-in `___` blank, Hindi "निकटतम पूर्णांक") only when no usable options were found; subjective requires an instruction verb ("explain/describe/derive/prove/…", Hindi "समझाइए/व्याख्या/सिद्ध कीजिए") again only when no options were found. Weak evidence leaves the item a single-correct MCQ, so the existing "minimum two options" check still catches genuinely broken MCQs.
- **Effect on the pipeline.** Numerical and subjective items are no longer reported as broken MCQs; they are flagged with a type-specific note that preserves their content and tells the reviewer to enter the answer manually or exclude the item. Multiple-correct items keep all their options but are flagged so they are not silently graded as single-correct. The detected type is shown as a badge on the review page and is editable in the review form (never used for grading). On approval it maps to the bank's `question_type` (multiple-correct → MCQ-multiple, numerical → numerical; subjective has no bank equivalent and stays single-correct until a reviewer converts it), and the duplicate-detection guard now refuses to link items whose types differ. Essay/subjective remains an **unsupported** bank type by design.
- **Multi-drive private storage fix.** `PrivatePracticeStorage.location` used `os.path.commonpath`, which raises `ValueError` when the private root and `MEDIA_ROOT`/`STATIC_ROOT` are on different Windows drives (e.g. project on `A:` and a temp `MEDIA_ROOT` on `C:`). Different drives cannot nest, so this is now treated as "safely separate" instead of erroring. This removes a crash for multi-drive deployments and unblocked ~20 private-practice tests on this two-drive machine; the separation guarantee is unchanged.
- **Tests run (this session, Python 3.12.10 / PyMuPDF 1.28.2).** New `apps/questions/test_question_types.py` (14 tests): unit coverage of the classifier across English and Hindi phrasings and negative cases (ordinary MCQs with cue-like words such as "correct"/"describes"/"value of" are not misclassified; a cue-less broken MCQ stays single so the two-option check still fires), plus end-to-end extraction of a synthetic mixed-type PDF (single/numerical/multiple-correct/subjective) asserting the detected type, the flag, that content is preserved and never reported as a broken MCQ, the review-page badges, and the approval type-mapping and duplicate-guard behaviour. The full **`apps.questions` suite passed 245/245 (9 skipped)**; `apps.accounts` 13/13, `apps.exams` 39/39, `apps.core` 11/11 (1 skipped), `apps.payments` 12/12 all passed. `manage.py check` and `makemigrations --check --dry-run` report no issues and no pending migrations; `git diff --check` is clean.
- **What was not run / remains unverified.** The 9 skips are the optional Chromium browser E2E workflows (Playwright is not installed on this machine) and the real local English/Hindi OCR regressions (no Tesseract executable or language data on PATH / `TESSERACT_CMD`); these were therefore **not** exercised this session. The 26-page sample and the newer AITS 02 paper were not available, so no original-paper regression was re-run here. The detector is heuristic text analysis, not comprehension: unusual phrasings, image-only numerical prompts, and mixed-type items can still be mislabelled, which is why every non-single type is flagged for human confirmation. The scratch script `scratch/verify_phase3.py` writes to the shared local `db.sqlite3`, is not idempotent, and its step-8 duplicate assertion reflects older, looser dedup behaviour; it fails independently of these changes (confirmed by re-running with the new dedup condition removed) and is not part of the automated suite.
- **Setup note.** Apply the new migration with `python manage.py migrate questions` (adds `extractedquestion.detected_type`). No new Python dependencies are introduced.

## Stacked-fraction reconstruction and diagram isolation — 2026-11-12 (real-paper driven)

A real 27-page two-column NEET practice paper (a **student-private** upload, processed **locally only** and never sent anywhere, never committed) exposed two concrete extraction failures that applied to many questions, not just one PDF:

- **Vertically-stacked fractions were scrambled.** Options rendered as a numerator over a rule over a denominator (e.g. `R/8 inside the cone`, `−800/3 J`) were read in flat order as numerator, then the option text, then the denominator — producing `inside the cone 8 R` and leaking the numerator into the end of the question statement. The cause: PyMuPDF's reading order splits the two halves of a stacked fraction onto separate lines, and the previous `reconstruct_option_fractions` only handled Type3-math-font fractions behind a `has_complex_math` gate, so full-size ruled fractions were never touched.
- **Fix (`pdf_math.inline_stacked_fractions`, wired into `DigitalQuestionLayout._text_in_rect`).** When a short horizontal rule has clear numerator glyphs directly above it and denominator glyphs directly below it, the two are combined into a single `num/den` token placed on the rule's own line, and the region's words (never altered internally) are regrouped into visual lines. It returns `None` — leaving PyMuPDF's native text untouched — whenever no reliable fraction rule is found, so non-fraction regions are unaffected. Rules wider than 120pt (table/section dividers) and numerators/denominators longer than 24 characters are rejected, so a table divider is never mistaken for a fraction. This fixes both the mangled options and the numerator leak, and it also lets the existing superscript repair recover forms like `M²` in dimensional formulae. It is pure local geometry — no network, model or paid service — and never drops or invents words.
- **More diagrams are now isolated.** `_vector_candidates` previously clustered every vector on a dense page — fraction bars, underlines and separators included — into one page-sized blob that exceeded the 30%-area limit and was discarded, so real figures were missed. Thin straight rules are now excluded before clustering (a new `_is_thin_rule`), so genuine line-art clusters separate out. On the real paper this raised the number of questions with a detected figure or candidate crop substantially. Candidates remain conservative: size, area, table-overlap, column-containment and option-position guards are unchanged, and every automatic figure is still flagged for human review.
- **Known remaining limit — column-crossing diagrams.** A figure whose vector bounding box spans into the adjacent text column (common because PyMuPDF inflates a path's bbox with Bézier control points) is still left for manual review rather than auto-cropped, because cropping it could pull in the neighbouring column's text. The figure stays visible in the original-source excerpt so a reviewer can crop and assign it with the existing tools. Scanned/raster diagrams and borderless figures can still be missed; nothing is auto-attached when ownership is ambiguous.
- **Tests.** New `apps/questions/test_fraction_layout.py` (5 tests) builds synthetic PDFs that reproduce the stacked-fraction geometry (including a negative-numerator work/energy case and a wide-divider negative case) and asserts correct option text, no numerator leak into the statement, and that plain MCQs and wide rules are left untouched. The regression fixtures are synthetic; the real private PDF was **not** added to the repository. The full **`apps.questions` suite passed 245/245 (9 skipped: Playwright and Tesseract unavailable)** both before and after these changes; `manage.py check`, `makemigrations --check` and `git diff --check` are clean. Correctness of the real paper's many figures was assessed via the detector's geometric guards and aggregate detection counts, not by rendering the private document's crops.
- **Applying it to an already-processed paper.** Extraction deliberately refuses to overwrite existing staged review work, so a paper uploaded before this change keeps its old results; re-upload the PDF to extract it with the improved pipeline.

## Optional local MinerU extraction backend — 2026-11-12

A new, **off-by-default** local extraction method uses [MinerU](https://github.com/opendatalab/MinerU) for dramatically better recovery of fractions, formulas, figures and tables, while keeping the project's free/local/no-upload guarantees.

- **How it runs.** MinerU's heavy ML stack lives in a **separate virtualenv** and is invoked **as a subprocess** (`apps/questions/mineru_runner.py`, executed by `settings.MINERU_PYTHON`), so none of its dependencies enter the web app. Parsing is **fully local**: telemetry is disabled (`MINERU_TELEMETRY_DISABLED=1`), the cloud `--remote` service is never used, and the only network access is a one-time download of model *weights* (never the document). The subprocess emits a `content_list.json` + cropped figure images; `apps/questions/mineru_extractor.py` converts that into the normal `ExtractedQuestion`/`ExtractedFigure` staging records, so the existing review, flagging, privacy, copy-on-write and approval workflow is unchanged. Every MinerU item is flagged for human review; nothing is auto-confirmed.
- **Where it's offered.** A new `ExtractionMode.LOCAL_MINERU` appears in the upload form **only when `MINERU_PYTHON` is configured**, is validated server-side, and always runs as a **background Celery job** (it is slow). If unconfigured or the subprocess fails/times out, the paper is marked FAILED with a clear log and **existing review work is never overwritten**.
- **Measured quality (local, on the supplied private AITS NEET paper — processed locally only, never uploaded, never committed).** On the hard content the built-in pipeline struggles with, MinerU produced: option fractions as clean LaTeX (`$\frac{R}{8}$ inside the cone`, `$-\frac{800}{3}\,\mathbf{J}$`, `$\frac{1}{\sqrt{3}}$`), dimensional formulas with brackets and signed superscripts (`$\left[\mathbf{M}^2\mathbf{L}^{-1}\mathbf{T}^{-3}\right]$`), nested formulas (`$F=\frac{A-x^2}{Bt}+\frac{C}{\sqrt{x}}\exp(-\frac{Dt^2}{x})$`), vectors, and — crucially — it **extracted and correctly cropped the cone+hemisphere diagram** (and a collision figure) that the built-in pipeline missed because those vectors cross the column boundary. Residual MinerU slips remain (e.g. it read "h = 3R" as "h R = 3", and when a question number is dropped in a two-column break two questions can merge), which is exactly why output stays flagged.
- **Performance / footprint.** On this GPU-less Windows machine (Intel iGPU via DirectML + CPU) MinerU ran at **~40 s/page** once warm (≈18 min for a 27-page paper); a GPU cuts this roughly 10×. The venv (~several GB) and model weights (~1 GB cache) are **not** committed. `mineru[core]` alone is a thin client — the local torch pipeline needs `mineru[torch]`; effort `medium` uses the torch/ONNX pipeline (layout + formula recognition + OCR + tables) and deliberately avoids the `high`/`xhigh` VLM path, whose `llama.cpp` native component is blocked by some Windows Application Control policies.
- **Tests.** New `apps/questions/test_mineru_extractor.py` (15 tests) covers the markup cleaner, math-aware option splitting (a `(2)` inside `$...$` is not an option), HTML-table→structured conversion (including ragged-table rejection), question/figure/table parsing from a synthetic MinerU content list, section-banner filtering, the configured/unconfigured gate, and the extractor itself with the **subprocess mocked** (so CI needs no MinerU install): successful staging with a primary figure, clean failure when unconfigured, subprocess-failure reporting, and preservation of existing review work. The parser was also validated against **real** MinerU output locally. Full `apps.questions` suite: **265/265 passed (9 skipped: Playwright and Tesseract unavailable)**; `manage.py check`, `makemigrations --check` and `git diff --check` clean.
- **Setup.** Create a separate venv at a **short path** (Windows long-path limit), `pip install "mineru[torch]"`, set `MINERU_PYTHON` (plus optional `MINERU_EFFORT`, `MINERU_MODEL_SOURCE`, `MINERU_MAX_PAGES`, `MINERU_TIMEOUT_SECONDS`) — see `.env.example`. Needs a running Celery worker (the job is long). MinerU weights download on first run. **Not tested on a GPU this session**; GPU throughput, and accuracy across diverse papers, remain to be validated by the operator.

## Broader local layout follow-up

- The local geometry pass now chooses one, two or three equal-width columns **per page** where there is sufficient evidence; mixed or ambiguous within-page layouts are flagged. A long, coherent plain-numbered sequence can override stray `Q1`/`Q2` references, and some incomplete trailing numbered questions are retained for manual review. Repeated answer labels near page edges no longer automatically become cropped headers/footers. Recognizable declared paper-wide totals are compared against extracted counts; a matching total is not proof of correctness, and unrecognized totals cannot be checked.
- Repeated, vertically paired question numbers can indicate parallel language columns. One text layer is selected using a readability heuristic and the other is kept, when its boundaries can be paired, as original-pixel source images and normalized provenance. This is not translation; a language can be selected incorrectly, matching or continuation boundaries may be missed, and the alternate text is not automatically made searchable. Source images must be checked for option order and content. The parser also recovers a complete A/C-over-B/D option grid only when all labels align and existing option tokens are conserved.
- Uncertain math, scans and tables can get bounded original-source screenshots in addition to extracted text. Review and CBT label these supplemental images; clicking an image opens it at full size. A detectable printed answer/solution blocks the affected source crop, but labels can be missed, and **image-only or unlabelled answers and unrelated content can still appear**. Inspect, remove or recrop unsafe images before test creation. If an option list is incomplete and conservative question boundaries are available, a bounded full-question image may be saved for manual repair without inventing choices. Full extraction notes, including some detected multi-answer and essay warnings, are visible in private review. At the time of that earlier layout review only single-choice MCQs were supported for scoring. The later typed-question upgrade adds numerical and multiple-correct scoring after explicit human key and rule confirmation; subjective items still need exclusion or manual conversion.
