# PDF-to-CBT upgrade: validation and limitations

This report records the work and tests performed in the current development session. It is not a claim that every question in any PDF is correct or that the application is production-ready.

## What changed

- Local digital-PDF extraction now retains question page/normalized regions, detects some ruled tables and merged cells, conservatively reconstructs certain superscripts, fractions and simple radicals, and flags uncertain mathematical/table content for review. Automatic figures are original-PDF crops; reviewers can attach, replace, retarget or crop multiple question/option figures. Cloud extraction validates optional structured tables and source-region suggestions, with human review required.
- Structured tables are escaped and rendered as real responsive HTML, with math rendering in cells and options, in staging, bank, CBT and results. The cell editor supports adding/removing rows and an advanced representation for spans. Assertion–Reason and statement labels are visually distinguished when recognized.
- Optional Gemini answer suggestions are consent-gated, model-configurable, validated and kept separate from grading keys. Reviewers can accept, edit or reject them. Missing/low-confidence/vision-dependent answers remain unconfirmed. The staging page offers a bounded queue of up to five **separate** requests; unchanged pending/suggested requests are deduplicated. Student plans provide configurable quotas; provider calls, reported tokens and optional cost estimates are recorded.
- Private practice remains owner-scoped with private files, server-side fixed expiry, reattempts and confirmed-key-only scoring. Results distinguish correct, incorrect, unattempted and answered-but-ungraded, show attempted totals and excluded keys, and include subject/topic, time and report views. Student bank edits use copy-on-write to protect existing private-test history. Institutional exam settings are not changed by a private test's duration. Razorpay remains test-mode-only with server verification.

## The supplied original paper — local only

The 26-page sample was processed locally; it was not sent to Mathpix, Gemini or any other provider. The independent check compared explicit `Q<number>` labels from the PDF text layer against the questions assigned to each page, rather than simply counting extractor output:

| PDF pages | Labels and detected questions by page |
| --- | --- |
| 1–6 | 0, 9, 7, 8, 5, 8 |
| 7–12 | 7, 7, 8, 10, 10, 9 |
| 13–18 | 6, 6, 8, 9, 8, 7 |
| 19–24 | 10, 8, 8, 7, 8, 6 |
| 25–26 | 1, 0 |

Across those pages, all **180 explicit labels** matched an extracted question on the same start page; each detected question had at least two uniquely labelled options. This checks numbering and gross option structure, **not** the correctness of every word, number, formula, option, or diagram. The run flagged 71 questions for review; unflagged questions are not certified. Ten questions contained detected structured tables. Twenty-five questions had an automatically attached primary figure crop and none had an automatically attached additional figure; missed/vector/option figures may still require manual work.

Selected source comparisons included Q44's distinct `g/√3` and fraction bar, Q45 and Q56's simple fractions, Q52's superscript, Q55's cross-column table, Q80's three simple table fractions, and Q94/Q150's header/body tables split across pages. These examples have automated regression assertions; they do not establish universal accuracy. At that earlier checkpoint, the local parser flattened some expressions, including Q16 option D; see the later local-extractor follow-up below. Review **every** question, source region, bilingual passage, table and figure before use. The supplied sample contains text-layer material, not a real scanned Hindi examination.

## Lower-cost extraction follow-up — 2026-11-03

PyMuPDF prepares local text and embedded-image candidates; Gemini receives page previews and text, with no Mathpix request or setup fee. Both the previous local and Mathpix + Gemini modes remain available. Each Gemini question is flagged, no answer is automatically confirmed, and missing scanned/vector figures may need manual cropping.
- The optional mode is off by default. Its model, thinking level, output limit and per-job pacing are separate from the Mathpix pipeline. ## Local extractor quality follow-up — 2026-11-04

- Improved local layout handling for plain numbered papers, mixed numbered/prefixed labels, common A)/1)/bracket/five-choice styles, same-line option images, and some ruled grids without an explicit table reference. Numbered lines with insufficient evidence are treated conservatively; gaps and incomplete items still need review.
- Local vector clusters and scanned-page non-text ink regions can yield original-PDF crops, including on a full-page raster with a pre-existing text layer; overlapping vector/scan candidates are deduplicated. Ambiguous or unreferenced candidates are placed in the review pool rather than assigned to a question. Their detection and ownership are heuristic; figures, labels, scans and borderless tables can still be missed. OCR-derived and candidate-graphic questions are flagged. Nothing is uploaded to a provider.
- OCR now processes scanned pages locally without discarding digital-page geometry from the rest of a mixed PDF. Clearly separated OCR word spans can regain spaces; this helped a generated Hindi fixture but is not language understanding. The primary path uses PyMuPDF's Tesseract integration and configured local English/Hindi `.traineddata`; the fallback requires the executable. Missing or failed OCR is reported and may leave pages/questions unread. Rendering is bounded for oversized pages and native processing failures are reported. No OCR data is bundled or downloaded by the application.
- On the original supplied paper, the latest run still found **180 labels, 25 primary figure crops and 10 table questions**, with 71 questions flagged in the in-memory layout pass. New geometry-backed regression checks recover Q16 option D and Q39's four fraction/radical choices and remove Q39's displaced option glyphs from its statement. This is not a transcription audit or evidence of overall accuracy. The newer problematic PDF has not been provided or tested.
- Synthetic cases cover numbered/two-column/continued layouts, answer formats, table boundaries, vector and scan candidates, OCR failures, private figure access and image-only options in both teacher-bank approval and a private CBT. With locally installed English and Hindi Tesseract data, real local OCR was also exercised on generated English and Hindi scans; these are small clean fixtures, not validation on a real scanned Hindi exam. Never infer an answer key or use an unreviewed extraction as authoritative.
- Final verification: **282/282** Django tests passed on Python 3.11 and PyMuPDF 1.28.2, including the original-paper regression, four Chromium workflows, and actual local OCR with English/Hindi language data. An additional **63/63** extraction/layout/original-paper tests passed at the declared minimum PyMuPDF 1.24.14. No real Mathpix, Gemini or Razorpay requests were made; provider and payment tests were mocked. `manage.py check`, migration consistency and `git diff --check` also passed.

## Free local extraction and keyless-comparison follow-up — 2026-11-06

- New synthetic fixtures reproduce interleaving of wrapped side-by-side options, dense borderless matching tables, and disconnected vector fragments in image-only options. The parser now reorders a complete option run only when its source tokens all remain accounted for; infers borderless tables only with an explicit table/matching reference, dense cells, source-word preservation, and clear boundaries above the choices; and preserves bounded original-pixel crops of disconnected option fragments, including across pages. Uncertain stem fragments go to the unassigned pool. All of these remain heuristic and are flagged for human review. Synthetic tests also check private/teacher ownership and private CBT image survival.
- Reprocessing the previously supplied 26-page PDF locally still produced **180 questions, 25 primary figures, 0 extra candidates, 10 table questions and 71 flagged questions**, with no question text, option, table, or figure-count changes versus the prior baseline. This is a regression comparison, not a proof that the extracted content is complete or correct. Only a screenshot naming the newer AITS 02 paper was supplied; that PDF was not tested.
- Added an optional, default-off, user-requested **local AI comparison after submission**, separate from confirmed grading. It checks cloud-disabled status and the installed model list before sending question text to a trusted loopback-only Ollama server, with redirects and proxies disabled. PDFs, images and the student's selection are not sent. Image-dependent and uncertain text/table questions are skipped. Comparisons may be wrong; no generated key is confirmed, no verified score is changed, and no paid provider is invoked. A new comparison uses one existing practice-plan AI allowance; resume does not consume another. The browser processes one question at a time; there is no background worker. No real Ollama model or runtime was available, so compatibility, performance and answer accuracy remain unverified. Local inference privacy depends on the operator's trusted, cloud-disabled, appropriately firewalled runtime.
- The cloud-configuration error shown after a rejected upload is now hidden when the user switches to local mode; switching back restores the relevant validation. The server still rejects unconfigured or unconsented cloud extraction.
- Final suite: **306/306 Django tests passed** on Python 3.11 / PyMuPDF 1.28.2, including five Chromium workflows, real local English/Hindi OCR on synthetic scans and the earlier supplied PDF. The AI browser and HTTP workflow used only a synthetic local stub; the 180-answer scale/resume test used a patched model function. A first full run exposed a SQLite in-memory live-server shutdown race; the new browser test now waits for pending network activity and closes its context, after which targeted browser/concurrency tests and the full suite passed. At the declared minimum PyMuPDF 1.24.14, **73/73** local extraction/layout tests passed with the same synthetic OCR data and prior PDF. `manage.py check`, migration consistency, `pip check`, JavaScript syntax checks and `git diff --check` passed. No real PDF was sent to a provider, and no live model or payment call was made.

## Remaining operational work

Obtain current provider terms/prices and operator credentials in a secret manager, configure explicit model IDs, and only with the owner's authorization run a small representative non-sensitive live test; compare results and cost with manual ground truth. Metadata capability checks cannot guarantee output quality or multimodal support.
2. Review all extracted content and image associations. Local OCR and geometry are heuristics; some diagrams, vector art, equations, borderless tables and content across page breaks may be missed. Correct or exclude items before publishing or taking a test.
3. Configure HTTPS, backups, private storage, production database, rate limits, logs, a Celery worker and beat (or cron for expiry), and a real deployment security review. Existing teacher-bank image edits can affect institutional exams/history; review downstream use before changing them. A private bank snapshot can outlive a deleted source PDF.
4. PDF report math is currently text rather than typeset, and Hindi searchable/copyable text may have ligature issues. Accessibility and real-world scanned Hindi OCR need independent validation. SQLite lock contention can return a safe retryable 503; use an appropriately configured production database.
